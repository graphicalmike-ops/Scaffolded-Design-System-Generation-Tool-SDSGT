

### Follow-up, 2026-10-14 — Demo-run generator bugs 1-3 fixed (Next.js + Tailwind + shadcn): theme import, percent opacity tokens, radius by name

Found in the 2026-10-08 Demo run, fixed and verified on real scaffolds (a "before" and an "after" project from the same seed, production builds, browser computed styles). (1) `ensureThemeImports` in `scaffold/nextjs.ts` adds `@import "./theme.css"` / `theme-light.css` (/ `theme-dark.css`) to the shadcn path's `globals.css`, idempotent and safe on `--update`. (2) `opacityLinesToPercent` in `generate/tailwind.ts` writes `--opacity-*` as percentages in `tailwind/theme.css`: with the file imported, unitless values made `bg-primary/10` compile to invalid `color-mix()` and every colour-opacity class (including vendored shadcn ones) computed to `rgba(0,0,0,0)`; the plain `opacity-50` class was unaffected. (3) `generate/shadcn.ts` binds `--radius-sm/md/lg/xl` to the same-named radius tokens (2xl/3xl/4xl cap at xl) and sets `--radius` to `radius.lg`; measured Button 6px to 8px, Card 8.4px to 16px with the Bootstrap preset. The Figma components plan derives radii by name too (`exactRadiusLg`, `exactRadiusStep`, `shadcnRadiusPx`): 15 components' radius variables changed and 10 now-unneeded 'nearest token' notes disappeared; already-pushed Figma sets keep the old radii until re-pushed. QA: core 16/16 (2672 checks, with two new regression checks) and cli 6/6. Not changed: the shadcn-vue scaffold path (it does not copy `theme.css`). Still open: figma-pull float32 rounding.

**Same day, shadcn-vue path:** `scaffold/vuejs.ts` had the same import gap and also never copied `theme.css`/`theme-light.css`/`theme-dark.css` on the `--shadcn` branch (only the plain Tailwind branch did). It now copies the three files on both branches and runs `ensureThemeImports` on `src/assets/main.css` (the helper moved to `shared/scaffold-common.ts`, shared with `nextjs.ts`). Verified on a real Vue shadcn build: imports present once and not duplicated by `--update`, compiled `--radius-xl:16px`, `--opacity-*` as percentages, core QA 16/16 and CLI QA 6/6.

**Same day, Demo-run bug 4 (figma-pull float32 noise):** `promote/figma-pull.ts` now rounds every plain number from Figma to 2 decimals before comparing (live input, stored baseline, new baseline), so float32 noise (`0.05` read back as `0.0500000007`) no longer shows up as a change or lands in token files. Colour alphas keep their 0.001 tolerance. New QA case CLI-7 (clean baseline + noisy live = 0 changes; old noisy baseline = 0 changes; a real edit = one clean value); confirmed it fails with the fix removed.

**Same day, Figma rings on fill-less variants:** verified live that `showShadowBehindNode: false` + a 0.01% white fill makes the ring draw on frames with no fill (main components and instances); replay, plan disclosures and the existing test sets updated (see `figma-component-variations-plan.md`, "Rings on fill-less variants"). This also closes the Button description's missing ring-limit note: there is no longer a limit to disclose.
